# Lesson 00-1: この教材の使い方

## Concept

この教材は「読んで理解する」ものではなく、「**考えてから確かめる**」ものです。
そのため、各 Lesson は答えを最初に見せません。

このページでは、1つの Lesson の読み方を説明し、そのあと実際に1問解いて体験します。

## 1つの Lesson の読み方

Chapter 01〜16 の Lesson は、どれも同じ順番の節でできています。

| 節 | 書いてあること | あなたがすること |
| --- | --- | --- |
| **Concept** | この Lesson で学ぶ考え方を、短く | ざっと読む |
| **Why?** | なぜそれが必要か。何に困るのか | 自分の経験と結びつけて読む |
| **Bad Example** | 問題のあるコード | すぐに答えを探さず、コードを読む |
| **Problem** | そのコードで何が起きるか | どんな入力・使い方で困るかを想像する |
| **Think** | 問い | **ここで手を止めて、自分の答えを決める**（いちばん大切な節） |
| **Hint** | 考えるための手がかり（折りたたんである） | 詰まったときだけ、1つずつ開く |
| **Solution** | 考え方の例（折りたたんである） | 自分の答えと比べる。違っていたら、どこで分かれたかを考える |
| **Deep Dive** | 一歩踏み込んだ話 | 余裕があれば読む。後で戻ってきてもよい |
| **Exercise** | `cargo test` で判定する演習 | 手元で解く（準備は次の 00-2 で説明します） |
| **Challenge** | 発展の課題 | 余裕があれば挑戦する。答えは用意していない |
| **Review** | 振り返りのチェックリスト | 各項目を、**自分の言葉で説明できるか**確かめる |

Lesson によっては、節の名前が少し違ったり、一部の節が無かったりします。
それでも、「問いが出たら手を止める」「答えは折りたたみの中」という形は同じです。

> **Solution は「正解」ではありません。**
> この教材の問いの多くは、答えが1つに決まりません。
> Solution にあるのは考え方の**例**です。自分の答えと違っていても、理由を説明できるなら、それは十分に良い答えです。

## やってみよう: コンパイルエラーを読む

上の流れを、実際に1問で体験してみましょう。

この教材では、コンパイルエラーを「直して終わり」にしません。
まず次のコードを読んでください。**コンパイルは通るでしょうか？**

```rust,compile_fail,E0505
fn main() {
    let x = String::from("hello");
    let y = &x;

    drop(x);

    println!("{y}");
}
```

### Think

ここで手を止めて、次の3つに自分の答えを決めてください。

1. 何が borrow（借用）されていますか？
2. なぜ `drop(x)` できないのですか？
3. コンパイラは何を保証しようとしていますか？

<details>
<summary>Hint</summary>

`y` が最後に使われる場所と、`drop(x)` の場所の順序に注目してください。

</details>

<details>
<summary>Solution</summary>

このコードは**コンパイルできません**（エラー E0505: cannot move out of `x` because it is borrowed）。

1. `let y = &x;` により、`x` は `y` から借用されています。
2. `drop(x)` は `x` の所有権を move して破棄します。その後も `println!("{y}")` で `y` が使われるため、`y` は解放済みのメモリを指すことになります。
3. 「参照が生きている間は、参照先が生きている」ことです。これが、解放済みのメモリを指す参照（dangling reference）を防ぐ仕組みです。

修正は、`println!` を `drop(x)` の前に移す（借用の期間を先に終わらせる）か、`y` が不要になるように設計を見直すことです。
どちらが望ましいかは、**なぜ `x` を早く破棄したいのか**によります。この問いの掘り下げは、Chapter 01 で行います。

</details>

いかがでしたか。
コードを見てすぐに答えが浮かんでも、Hint や Solution を開く前に、**一度自分の言葉にしてみる**ことが大切です。
「なんとなく分かる」と「説明できる」の間には、思ったより大きな差があります。

> このページのコードは、`mdbook test`（本のコード例を実際にコンパイルして確かめる仕組み）によって、「**実際にコンパイルに失敗すること**」が検証されています。
> 教材の説明と、実際のコンパイラの動きがずれることはありません。
