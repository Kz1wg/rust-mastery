# 02 Type Design

この章の中心的な考え方は、次の一文です。

> **不正な状態を、型の上で表現できないようにする。**

バリデーション関数を呼び忘れるバグ、引数の順序を取り違えるバグ、意味のない値の組み合わせ。
これらは「注意深く書く」ことではなく、**型の設計**で減らせます。

## この章の到達目標

- `bool` や `String` が「表現できてしまう不正な状態」を指摘できる
- newtype を使うべき場面と、**使わなくてよい場面**を区別できる
- 「検証する」のではなく「検証済みの型を作る」設計ができる
- フィールドの公開範囲が、不変条件の保証にどう関わるか説明できる
