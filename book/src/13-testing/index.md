# 13 Testing

テストは「バグを見つける作業」だと思われがちですが、この章ではもう1つの顔に注目します。
**テストを書こうとしたときに感じる「書きにくさ」は、設計の問題を教えてくれるサイン**だ、ということです。

この教材の演習はすべて `cargo test` で判定してきました。この章では、その仕組みを
「使う側」から「設計する側」へと視点を移して見直します。

## この章の到達目標

- テストしにくいコードを見て、どこを分ければテストしやすくなるか判断できる
- 単体テスト・統合テスト・ドキュメントテストの違いと、それぞれの置き場所を説明できる
- 成功する場合だけでなく、失敗する場合（`Err` や panic）をテストできる
