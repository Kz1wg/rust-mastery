# 16 Library Design

ライブラリを作るということは、**自分以外の誰かが、自分のコードを前提にコードを書く**ということです。
アプリケーションなら自分の都合でいつでも変えられたものが、ライブラリでは「約束」になります。

この章は、これまでの章の総まとめでもあります。
型設計（02, 03）、trait（04）、エラー設計（06）、公開範囲（12）で学んだことを、
**利用者の目から見直す**のがこの章の役割です。

## この章の到達目標

- 利用者の立場で、公開APIの使いにくさや危うさを指摘できる
- どんな変更が「利用者を壊す変更（破壊的変更）」なのかを判断できる
- 利用者が迷わず使えるドキュメントとコード例を書ける
