# 17 Practical Projects

ここまでの章では、1つの Lesson で1つの考え方を学んできました。
実践プロジェクトでは、**いくつもの章の考え方を組み合わせて、1つの小さなツールやライブラリを作ります**。

実際の開発では、「この場面は Chapter 06 の話」と教えてくれる人はいません。
自分で「ここはエラーの種類を enum にすべきだ」「ここは入力を外から受け取ればテストしやすい」と気づく必要があります。
プロジェクトはその練習です。

## 演習との違い

| | 演習（`exercises/`） | 実践プロジェクト（`projects/`） |
| --- | --- | --- |
| 大きさ | 関数を数個 | 小さなツール・ライブラリ1つ |
| 扱う章 | 主に1つ | 複数の章をまたぐ |
| 依存crate | 使わない（標準ライブラリのみ） | 必要なら使う（P6 で tokio を使う） |
| 実行する場所 | リポジトリのルート | `projects/` の中 |

プロジェクトのコードは、GitHub のリポジトリの [projects/](https://github.com/Kz1wg/rust-mastery/tree/main/projects) ディレクトリにあります。
まだリポジトリを手元に用意していない場合は、[Lesson 00-2](../00-introduction/00-2-cargo-test.md) の「演習はどこにあるか」を見てください。

`projects/` は、ルートとは**別の workspace** になっています。
依存crateを持ち込む範囲を、このディレクトリの中に限るためです（Lesson 12-3）。

## 進め方

```bash
cd projects
cargo test -p p01_wordstat        # 1つのプロジェクトを判定
cargo run -p p01_wordstat -- --top 3 notes.txt   # CLI として動かす（P1）
```

各プロジェクトのページには、次のものがあります。

1. **何を作るか**: 完成したときの動き
2. **使う章**: どの章の考え方を組み合わせるか
3. **設計の問い**: 手を動かす前に考えてほしいこと（考え方の例は折りたたんであります）
4. **進め方**: どの順番で実装すると進めやすいか
5. **判定と振り返り**

型や関数のシグネチャは、演習と同じく用意してあります。本体の `todo!()` を実装してください。
ただし演習より大きいので、**一度に全部書かず、テストを1つずつ通していく**進め方をおすすめします。
