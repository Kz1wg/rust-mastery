# P4: 再試行つき HTTP クライアント

## 何を作るか

Web サーバーに GET リクエストを送り、一時的な失敗なら**やり直す（再試行する）**クライアントです。

```rust,ignore
let client = Client::new(StdTransport, "http://localhost:8080/api").with_max_retries(2);
let response = client.get("users")?;   // http://localhost:8080/api/users に GET
```

| 返ってきたもの | どうするか | 理由 |
| --- | --- | --- |
| 2xx・3xx | 成功として返す | |
| 4xx（404 など） | **再試行せず**、エラーを返す | 呼び出し側の間違い。何度送っても同じ |
| 5xx（503 など） | 再試行する | サーバーの一時的な問題かもしれない |
| 通信の失敗 | 再試行する | ネットワークの一時的な問題かもしれない |

## 設計の問い

> **問い1**: このプロジェクトでは `Transport` trait を作りました。P3 では「実装が1つなら trait を作らない」と判断しました。何が違うのでしょうか。

<details>
<summary>考え方の例</summary>

Lesson 04-1 に、trait を「今」作ってよい理由として「**テストのために偽物へ差し替えたい**」がありました。
このプロジェクトはまさにそれです。

本物の通信を使うテストは、ネットワークの状態に左右され、遅く、「5xx が返ってきた場合」を狙って起こすこともできません。
偽物に差し替えれば、「1回目は 503、2回目は通信失敗、3回目で成功」のような状況を、いつでも同じように再現できます。

実装が2つ（本物の `StdTransport` とテスト用の偽物）あり、両方を同じように扱う呼び出し側（`Client`）がいる——
trait を作る理由が、実際にあるわけです。

</details>

> **問い2**: `Transport::send` は `&self` を受け取ります。`&mut self` ではないのはなぜでしょうか。
> その結果、テスト用の偽物は何を使う必要がありましたか。

<details>
<summary>考え方の例</summary>

`&mut self` にすると、`Client::get` も `&mut self` にしなければならず、
**1つのクライアントを複数の場所から同時に使えなく**なります。
「送る」という操作は、利用者から見れば状態を変える操作ではないので、`&self` が自然です。

一方、テスト用の偽物は「送られたリクエストを記録する」「用意した応答を順に取り出す」という、状態を変える処理をします。
`&self` のまま状態を変えるために、`RefCell` を使っています（Lesson 10-3）。
本物の実装は状態を持たないので、`RefCell` は要りません。

</details>

> **問い3**: 4xx を再試行しないのはなぜでしょうか。逆に、再試行すると何が困りますか。

<details>
<summary>考え方の例</summary>

4xx は「リクエストが間違っている」という意味です（404 はそのURLが無い、400 は形式が間違っている、など）。
同じリクエストを何度送っても結果は変わらないので、再試行は時間の無駄になり、サーバーの負担も増やします。

「どの失敗なら再試行する価値があるか」は、失敗の**種類**を区別できて初めて判断できます。
これは Chapter 06 で、`Err` を種類ごとの enum にした理由と同じです。

</details>

## 本物の Transport について

`StdTransport` は、標準ライブラリの `TcpStream` で HTTP/1.1 を話す実装で、**完成した状態で用意してあります**。
読み物として、また「差し替えられる」ことの確認に使ってください。

テストの `real_transport_against_a_local_server` では、自分のマシン（`127.0.0.1`）に小さなサーバーを立て、
`StdTransport` を使った `Client` で通信しています。外部のネットワークには出ません。
**`Client` のコードは、偽物のときと1行も変わっていない**ことに注目してください。

実務では `reqwest` や `ureq` を使ってください。https、リダイレクト、タイムアウト、文字コードなど、
`StdTransport` が扱っていないことが多くあります。

## 進め方

1. **`url_for`**: `trim_end_matches('/')` と `trim_start_matches('/')` でつなぐ
2. **`get`**: `match` で「2xx・3xx」「4xx」「5xx」「通信の失敗」の4つに分ける。
   `match` のガード（`Ok(r) if r.status < 400 =>`）を使うと書きやすい
