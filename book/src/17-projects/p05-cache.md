# P5: 有効期限つきキャッシュ

## 何を作るか

一度計算した結果や、取得に時間のかかるデータを、**一定時間だけ覚えておく**仕組みです。
複数のスレッドから同時に使えます。

```rust,ignore
let cache = Arc::new(Cache::new(60, Arc::new(SystemClock)));   // 60秒で期限切れ

let price = cache.get_or_insert_with("7203", || fetch_price("7203"));  // 無ければ取得して覚える
let again = cache.get_or_insert_with("7203", || fetch_price("7203"));  // 60秒以内なら、覚えた値を返す
```

| 操作 | 動き |
| --- | --- |
| `insert(key, value)` | 覚える。同じキーなら上書きし、期限も延ばす |
| `get(key)` | 期限内なら値を返す。期限切れなら消して `None` |
| `get_or_insert_with(key, make)` | あれば返し、無ければ `make()` で作って覚える |
| `stats()` | ヒット（見つかった）数とミス（見つからなかった）数 |

## 使う章

| 章 | このプロジェクトでの使いどころ |
| --- | --- |
| 10-2 共有と可変性 | 中身を `Mutex` で守り、`Arc` で包んでスレッド間で共有する |
| 10-1 Send / Sync | `Cache` が `Send + Sync` になること（`Clock` にも `Send + Sync` を要求する理由） |
| 13-1 テスト可能な設計 | 現在時刻を `Clock` trait で受け取り、テストでは時計を自由に進める |
| 10-2 Challenge | ヒット数・ミス数を `AtomicU64` で数える（ロックを取らない） |

## 設計の問い

> **問い1**: 「60秒で期限切れになる」ことを、テストで確かめるにはどうすればよいでしょうか。

<details>
<summary>考え方の例</summary>

本当に60秒待つテストは遅すぎますし、`thread::sleep` を使ったテストは環境によって不安定になります。

そこで、現在時刻を `Clock` trait で**外から受け取る**ようにしています（Lesson 13-1）。
テストでは、`advance(3600)` で好きなだけ時計を進められる偽物を渡します。
こうすると「1時間後に期限切れになる」ことを、一瞬で、いつでも同じように確かめられます。

「期限のちょうど1秒前は有効、ちょうどで切れる」という**境目**も、はっきりテストできます（Lesson 13-3）。

</details>

> **問い2**: ヒット数とミス数は、`Mutex` の中ではなく `AtomicU64` で数えています。なぜでしょうか。

<details>
<summary>考え方の例</summary>

数を1増やすだけのために、キャッシュ全体のロックを取る必要はありません。
`AtomicU64::fetch_add` は、ロックなしで安全に数を増やせる操作です。

`stats()` のように「数を読むだけ」の呼び出しが、キャッシュの中身へのアクセスを待たせることもなくなります。
ただし、`AtomicU64` が守れるのは**1つの数**だけです。「ヒット数とミス数を、同じ瞬間の値として読む」ことは保証されません。
統計として眺める用途なら問題ありませんが、厳密に揃った値が必要なら、ロックの中で数える設計になります。

</details>

> **問い3**: `get_or_insert_with` で `make()` を呼んでいる間、ロックを持ち続けるべきでしょうか。

<details>
<summary>考え方の例</summary>

この実装では、**ロックを持たずに** `make()` を呼んでいます（`get` と `insert` を別々に呼ぶ）。

| 選択 | 良い点 | 困る点 |
| --- | --- | --- |
| ロックを持たずに `make()` を呼ぶ（この実装） | `make()` が遅くても、他のキーへのアクセスを止めない | 同時に同じキーを要求されると、`make()` が2回呼ばれることがある |
| ロックを持ったまま `make()` を呼ぶ | `make()` は必ず1回だけ | `make()` が遅い（ネットワーク通信など）と、**キャッシュ全体**が止まる |

Lesson 10-2 の「ロックを持ったまま、時間のかかる処理をしない」を優先した選択です。
「同じ計算が2回走っても、結果が同じなら困らない」場面では、これで十分です。
どうしても1回にしたい場合は、キーごとに別のロックを持つなど、設計が一段複雑になります
（実務では、この問題を解決済みの `moka` などの crate を検討してください）。

</details>

## 進め方

1. **`insert`**: ロックを取って `Entry` を入れる
2. **`get`**: 見つかって期限内 / 見つかったが期限切れ / 見つからない、の3つに分ける。それぞれで数を増やす
3. **`len`**: 期限内の項目だけを数える
4. **`get_or_insert_with`**: `get` と `insert` を組み合わせる
