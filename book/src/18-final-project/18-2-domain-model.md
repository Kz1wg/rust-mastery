# 18-2 Domain Model: 登場するものと、そのルール

## この段階でやること

要件に出てくる「もの」と、それらの**関係**と**ルール**を整理します。
ここで言う「ドメイン」とは、プログラムが扱う**現実の世界の側の仕組み**のことです。
例題なら、本・利用者・貸出と、「貸出中の本は借りられない」といったルールがドメインです。
ファイルやコマンドライン引数は、ドメインではありません（それは道具の側の話です）。

まだ Rust の型は書きません。**図と表**で考えます。

## 入力と出力

| 受け取るもの | 書くもの |
| --- | --- |
| 18-1 の要件 | 登場するもの / 状態の移り変わり / ルールの一覧（どの要件から来たか）/ 「その事実を誰が覚えるか」 |

## 考える問い

1. 要件の文の**名詞**を拾ってください。そのうち、ID を持って区別されるもの（「あの本」「この人」）はどれですか？
2. **状態が変わる**ものはどれですか？ どんな状態があり、どの操作で移りますか？
3. ルールを1つずつ書き出し、それが**どの要件から来たか**を書いてください
4. 同じ事実を、2か所で覚えていませんか？（例: 本の側の「貸出中」と、利用者の側の「借りている本の一覧」）
5. 1つのルールを確かめるのに、**複数のもの**を見る必要がありますか？ それは誰が確かめますか？

## 例題の設計メモ

<details>
<summary>例題の設計メモ（Domain Model）</summary>

### 登場するもの

| もの | 区別のしかた | 持っている情報 |
| --- | --- | --- |
| 本 | 本の ID | 書名、状態 |
| 利用者 | 利用者の ID | 名前 |
| 貸出 | （本1冊につき、同時に1つまで） | 借りた人、貸出日、返却期限 |
| 図書室 | （1つだけ） | 全ての本、全ての利用者 |

「貸出」は、本や利用者のように単独で存在するものではありません。
**本が貸出中のあいだだけ存在する**情報です。

### 本の状態の移り変わり

```text
            borrow（R3〜R6 を満たすとき）
  ┌────────┐ ─────────────────────▶ ┌────────────────────┐
  │ 貸出可 │                        │ 貸出中（貸出の情報） │
  └────────┘ ◀───────────────────── └────────────────────┘
               return（R7）
```

状態は2つだけです。「貸出中」のときにだけ、借りた人・貸出日・返却期限があります。

### ルールの一覧

| ルール | 来た要件 | 確かめるのに見るもの |
| --- | --- | --- |
| 本の ID は重複しない | R1 | 全ての本 |
| 利用者の ID は重複しない | R2 | 全ての利用者 |
| 借りられるのは貸出可の本だけ | R4 | その本 |
| 借りている冊数 < 3 | R5 | **その人が借りている全ての本** |
| 延滞している本があれば借りられない | R6 | **その人が借りている全ての本**と、今日の日付 |
| 返却できるのは貸出中の本だけ | R7 | その本 |
| 返却日 ≧ 貸出日 | 18-1 の「決めたこと」 | その本の貸出 |

### その事実を、誰が覚えるか

「利用者 M1 が本 B1 を借りている」という事実を、どこに記録するかを考えました。

| 案 | 記録する場所 | 問題 |
| --- | --- | --- |
| A | 本の状態の中（貸出中なら、借りた人を持つ） | 「M1 が何冊借りているか」を知るには、全ての本を見る必要がある |
| B | 利用者の側に「借りている本の一覧」 | 「B1 は貸出中か」を知るには、全ての利用者を見る必要がある |
| C | 両方に記録する | 片方だけ更新して、もう片方を忘れると、**事実が食い違う** |

**A を選びました。**
本は1冊ずつしかないので、「この本は誰に貸しているか」は本の側に1つだけ記録するのが自然です。
全ての本を見るのは、図書室の規模（数百〜数千冊）なら問題になりません。
C の「食い違う可能性」は、コードをどれだけ注意深く書いても、ゼロにはできません。

### 複数のものにまたがるルールを、誰が確かめるか

R5・R6 は、「その人が借りている全ての本」を見ないと確かめられません。
本1冊や利用者1人だけを見ても判断できないので、**全ての本と利用者を持っている「図書室」**が確かめます。
本や利用者は、自分では何も判断しない、ただのデータにします。

</details>

## よくある失敗

| 失敗 | 何が困るか | 直し方 |
| --- | --- | --- |
| 同じ事実を2か所で覚える | 更新を1か所忘れると、データが食い違う | 事実ごとに「覚える場所は1つ」と決める。必要なら、もう片方は**計算で求める** |
| 状態を bool の組み合わせで考える | 「貸出中でない、かつ借りた人がいる」のような、ありえない組み合わせが生まれる（Lesson 02-1） | 状態の一覧を書き、状態ごとに持つ情報を決める |
| 全てのものに「振る舞い」を持たせようとする | 複数のものにまたがるルールを、どこに書けばよいか分からなくなる | ルールごとに「確かめるのに何を見るか」を書き、それを全部持っている場所に置く |
| ファイルや画面のことを混ぜる | 「保存するときは〜」がドメインの図に入ると、保存形式を変えるたびにドメインが変わる | ドメインは「現実の図書室にもあるもの」だけで描く |
