# A. Compiler Error 読解集

この付録は、本文に出てきたコンパイルエラーを、**エラーコード別**にまとめたものです。
エラーに出会ったときの辞書として使ってください。

各エラーについて、次のことを書いています。

- **メッセージ**: 実際に表示される1行目（Rust 1.95 で確認。バージョンによって言い回しが少し変わることがあります）
- **守っているもの**: コンパイラがこのエラーで何を保証しようとしているか
- **直し方と判断**: 直し方の候補と、どれを選ぶかの目安
- **本文**: そのエラーを扱っている Lesson

## エラーの読み方

### 表示の各部分

```text
error[E0502]: cannot borrow `v` as mutable because it is also borrowed as immutable   ← ①
 --> src/main.rs:4:5                                                                  ← ②
  |
3 |     let first = &v[0];
  |                  - immutable borrow occurs here                                   ← ③
4 |     v.push(4);
  |     ^^^^^^^^^ mutable borrow occurs here                                          ← ④
5 |     println!("{first}");
  |                ----- immutable borrow later used here                             ← ⑤
```

| 番号 | 部分 | 読み方 |
| --- | --- | --- |
| ① | コードと要約 | 何の規則に反したか。コードで、この付録や `rustc --explain E0502` を引ける |
| ② | 場所 | ファイル名:行:列。エディタで開く場所 |
| ③〜⑤ | ラベル | `^^^` がエラーの起きた場所、`---` が関係する場所。**全部を順番に読む**と、「どこで借りて、どこで書き換えて、どこでまだ使っているか」という**物語**になっている |

`note:` や `help:` が続くこともあります。`help:` には直し方の提案が書かれていますが、
それが**設計として望ましい直し方とは限りません**（下の「5つの問い」を参照）。

### 最初のエラーから読む

エラーが10個出ても、原因は1つということがよくあります。
1つ目の型の誤りが、それを使う全ての場所でエラーを起こすからです。
**一番上のエラーだけを直して、もう一度コンパイルする**のが近道です。

### 5つの問い（Lesson 01-2）

コンパイルエラーは、「直して終わり」にしないでください。次の順番で考えます。

1. 何が起きたか（何を借りて、何をしようとしたか）
2. なぜそれが許されないのか
3. コンパイラは、何を保証しようとしているのか
4. どう直せるか（候補を2つ以上）
5. どの直し方が、**設計として**望ましいか

`clone()` を足す、`'static` を付ける、`unsafe` で囲む、といった「とりあえず通す」直し方は、
4 の候補には入っても、5 の答えにならないことが多いです。

## 所有権と借用

### E0382: 移動した値を使った

- **メッセージ**: `` borrow of moved value: `s` ``（使い方によって `use of moved value` など）
- **守っているもの**: 1つの値の持ち主は1人だけ。持ち主が2人いると、片付け（解放）が2回起きる
- **よくある原因**: 変数を別の変数に代入した、関数に値のまま渡した、`for x in v` で `v` を消費した後にまた使った

| 直し方 | 判断 |
| --- | --- |
| 渡す側を借用（`&s`）にする | 渡した先が読むだけなら、第一候補 |
| 渡した先から値を返してもらう | 渡した先で加工するなら自然 |
| `clone()` する | 本当に2つの独立した値が必要なときだけ。エラーを消すために使うと、コピーのコストと「どちらが正しい値か」の混乱が残る |
| `Copy` にする | 小さな値（数や、数だけの struct）に限る。E0184 も参照 |

**本文**: [01-1](../01-ownership/01-1-move.md)、[01-3](../01-ownership/01-3-ownership-design.md)、[03-3](../03-enum-state-machine/03-3-typestate.md)（typestate では、遷移した後の古い状態を使えないことを、このエラーで保証する）

### E0499: 書き換えるための借用を2つ同時に作った

- **メッセージ**: `` cannot borrow `v` as mutable more than once at a time ``
- **守っているもの**: 同じデータを2か所から同時に書き換えない。片方の書き換えが、もう片方の前提を壊すのを防ぐ
- **よくある原因**: `&mut` を変数に入れたまま、もう一度 `&mut` を取った。struct の2つのフィールドを、メソッド経由でそれぞれ `&mut` で取ろうとした

| 直し方 | 判断 |
| --- | --- |
| 1つ目の借用を使い終えてから、2つ目を取る（順番を変える） | 多くの場合これで足りる |
| フィールドを直接借りる（`&mut self.a` と `&mut self.b`） | コンパイラは、別のフィールドなら同時に借りられると分かる。メソッド経由だと `self` 全体を借りたことになる |
| `split_at_mut` など、分けて借りるための関数を使う | スライスを2つに分けるとき |

**本文**: [01-2](../01-ownership/01-2-borrow-errors.md)、[08-2](../08-lifetimes/08-2-structs-with-references.md)、[15-1](../15-unsafe/15-1-what-unsafe-means.md)（unsafe でもこの規則は緩まない）、[15-2](../15-unsafe/15-2-safe-abstraction.md)

### E0502: 読んでいる途中で書き換えようとした

- **メッセージ**: `` cannot borrow `v` as mutable because it is also borrowed as immutable ``
- **守っているもの**: 読んでいるデータを、途中で変えない。とくに `Vec` は、要素を足すと中身を別の場所へ引っ越すことがあり、古い場所への参照が壊れる
- **よくある原因**: 要素への参照を持ったまま `push` した。iterator で回している最中に、同じコレクションを変更した

| 直し方 | 判断 |
| --- | --- |
| 参照を使い終えてから書き換える | 第一候補 |
| 参照ではなく値（や添字）を持つ | `let first = v[0];`（`Copy` な値なら）。添字は、要素が消えると別の要素を指すことに注意 |
| 変更を集めておいて、回し終えてから適用する | iterator の中で変更したいときの定石 |

**本文**: [01-2](../01-ownership/01-2-borrow-errors.md)

### E0505: 借りられている値を、移動しようとした

- **メッセージ**: `` cannot move out of `x` because it is borrowed ``
- **守っているもの**: 参照が生きている間は、参照先も生きている（ぶら下がった参照を作らない）
- **よくある原因**: 参照を持ったまま、元の値を `drop` した、関数に渡した、別の変数に移した

| 直し方 | 判断 |
| --- | --- |
| 参照の使用を、移動より前に済ませる | 第一候補 |
| 移動をやめ、借用で渡す | 移動先が読むだけなら |
| そもそも、なぜ早く手放したいのかを考える | 「早く解放したい」のか「所有権を渡す必要がある」のかで、設計が変わる |

**本文**: [00-1](../00-introduction/00-1-how-to-use.md)

### E0594: 変更できない場所に代入した

- **メッセージ**: `` cannot assign to `x`, as it is not declared as mutable ``（状況によって `` cannot assign to `*r`, which is behind a `&` reference `` など）
- **守っているもの**: `mut` と書いていない変数、`&` で借りたデータは変わらない。読む側がそれを前提にしてよい
- **よくある原因**: `let` に `mut` を付け忘れた。`&self` のメソッドの中でフィールドを書き換えようとした

| 直し方 | 判断 |
| --- | --- |
| `let mut` にする、`&mut self` にする | 変更が本来の役割なら、素直にこれ |
| `Cell` / `RefCell` / `Mutex` を使う（interior mutability） | 「外から見て変わらないが、中で記録を更新したい」（キャッシュ、呼び出し回数）ときだけ。安易に使うと、「変わらない」という約束が崩れる |

**本文**: [10-3](../10-concurrency/10-3-interior-mutability.md)

### E0373: クロージャが、借りた値より長く生きるかもしれない

- **メッセージ**: `` closure may outlive the current function, but it borrows `v`, which is owned by the current function ``
- **守っているもの**: スレッドなどに渡したクロージャが、元の関数が終わった後に、消えた変数を使わない
- **よくある原因**: `thread::spawn` や `tokio::spawn` に、外の変数を借りるクロージャを渡した

| 直し方 | 判断 |
| --- | --- |
| `move` を付けて、値ごと渡す | そのスレッドだけが使うなら |
| `Arc` で包み、複製を `move` で渡す | 複数のスレッドで共有するなら |
| `thread::scope` を使う | スレッドが関数の中で必ず終わるなら、借用のまま渡せる |

**本文**: [10-1](../10-concurrency/10-1-send-sync.md)（関連: [11-3](../11-async/11-3-async-and-ownership.md) の `Send + 'static`、[P6](../17-projects/p06-fetch-all.md) の問い1）

## ライフタイム

### E0106: ライフタイムの指定が必要

- **メッセージ**: `missing lifetime specifier`
- **守っているもの**: 返す参照が、**どの引数から借りたものか**を、関数のシグネチャだけで分かるようにする
- **よくある原因**: 参照の引数が2つ以上あり、参照を返す関数。参照を持つ struct の定義

| 直し方 | 判断 |
| --- | --- |
| `<'a>` を付け、返す参照と、借り元の引数を同じ `'a` で結ぶ | どちらから借りるかが決まっているなら、その引数だけに付ける |
| 参照ではなく、所有する値（`String`）を返す | 借り元の寿命を呼ぶ人に意識させたくないなら |
| `'static` を付ける | 返すのが本当に文字列リテラルなどの場合だけ。エラーを消すために付けると、E0597 などが別の場所で出る |

**本文**: [08-1](../08-lifetimes/08-1-what-annotations-say.md)

### E0597: 借り元が、参照より先に消える

- **メッセージ**: `` `s` does not live long enough ``
- **守っているもの**: 参照は、借り元より長く生きない
- **よくある原因**: ブロックの中で作った値への参照を、ブロックの外で使った。`'static` を要求する場所に、一時的な値の参照を渡した

| 直し方 | 判断 |
| --- | --- |
| 値を、参照より外側のスコープで作る | 第一候補 |
| 参照ではなく、値そのものを持たせる | 借り元の寿命を管理したくないなら |

**本文**: [08-1](../08-lifetimes/08-1-what-annotations-say.md)、[08-3](../08-lifetimes/08-3-elision-and-static.md)、[08-4](../08-lifetimes/08-4-hrtb.md)、[09-2](../09-advanced-type-system/09-2-variance.md)

### E0515: 関数の中の値への参照を返した

- **メッセージ**: `` cannot return reference to local variable `s` ``（`` cannot return value referencing local variable `s` `` など）
- **守っているもの**: 関数が終わると消える値を、関数の外から参照させない
- **よくある原因**: 関数の中で `String` や `Vec` を作り、その `&str` や `&[T]` を返そうとした

| 直し方 | 判断 |
| --- | --- |
| 所有する値（`String`、`Vec<T>`）を返す | ほとんどの場合これが正解 |
| 呼ぶ側に置き場所を用意してもらい、そこへ書き込む | 大量のデータで、確保を減らしたいとき |

**本文**: [08-2](../08-lifetimes/08-2-structs-with-references.md)

### E0621: 引数の型に、ライフタイムの明示が必要

- **メッセージ**: `` explicit lifetime required in the type of `y` ``
- **守っているもの**: シグネチャで約束した借り元（`'a`）以外から借りた参照を、返さない
- **よくある原因**: 戻り値に `'a` を付けたのに、`'a` を付けていない引数から借りた値を返した

| 直し方 | 判断 |
| --- | --- |
| その引数にも `'a` を付ける | 本当にその引数から借りて返すなら |
| その引数から借りて返すのをやめる | シグネチャの約束のほうが正しいなら |

**本文**: [07-4](../07-iterator/07-4-borrowing-iterators.md)

### E0637: `'_` や `&` を、使えない場所で使った

- **メッセージ**: `` `'_` cannot be used here ``
- **守っているもの**: 「省略されたライフタイム」は、コンパイラが決められる場所でだけ使える
- **よくある原因**: 型や trait の定義の中で、名前のあるライフタイムが必要な所に `'_` を書いた

| 直し方 | 判断 |
| --- | --- |
| `<'a>` などの名前を付けて宣言する | その参照が何に結びつくかを、明示する |

**本文**: [05-4](../05-generics/05-4-gat-basics.md)

### E0700: `impl Trait` の戻り値が、宣言していないライフタイムを捕まえている

- **メッセージ**: `` hidden type for `impl Iterator<Item = i32>` captures lifetime that does not appear in bounds ``
- **守っているもの**: `impl Trait` の戻り値が、何を借りているかを呼ぶ人に隠さない
- **よくある原因**: 引数を借りる iterator を `impl Iterator` で返した（edition 2021 まで）
- **注意**: edition 2024 では、`impl Trait` が引数のライフタイムを自動で捕まえるように変わったため、同じコードでもこのエラーが出ないことがあります。この教材の演習は edition 2021 です

| 直し方 | 判断 |
| --- | --- |
| 戻り値に `+ '_` や `+ 'a` を付ける | 借りていることを、シグネチャで正直に示す |
| 借りずに、値を持つ iterator にする（`into_iter`、`collect`） | 借り元の寿命から切り離したいとき |

**本文**: [07-3](../07-iterator/07-3-laziness-and-allocation.md)

## 型と trait

### E0308: 型が合わない

- **メッセージ**: `mismatched types`
- **守っているもの**: 値は、宣言された型としてだけ使われる
- **よくある原因**: 本当に型を間違えた。**newtype の取り違え**（`BookId` を渡すべき所に `MemberId`）。`if` と `else` で違う型を返した。`impl Trait` で2種類の型を返そうとした

この教材では、E0308 を**味方**として使う場面がたくさんあります。
newtype や typestate は、「間違った使い方を E0308 にする」ための設計です。

| 直し方 | 判断 |
| --- | --- |
| 渡す値を正しくする | newtype の取り違えなら、それはコンパイラが見つけてくれたバグ |
| `impl Trait` で複数の型を返したいなら、`Box<dyn Trait>` か `enum` | 返す型が実行時に決まるなら |
| `as` や `into()` で変換する | 変換に意味があるときだけ。取り違えを変換で黙らせない |

**本文**: [02-2](../02-type-design/02-2-newtype.md)、[03-3](../03-enum-state-machine/03-3-typestate.md)、[04-2](../04-traits/04-2-generic-vs-dyn.md)、[05-3](../05-generics/05-3-impl-trait.md)、[09-1](../09-advanced-type-system/09-1-phantom-data.md)、[09-3](../09-advanced-type-system/09-3-type-level-constraints.md)、[18-3](../18-final-project/18-3-type-design.md)

### E0277: 必要な trait を実装していない

- **メッセージ**: `` the trait bound `T: Trait` is not satisfied ``、`` `Rc<i32>` cannot be sent between threads safely ``、`` the `?` operator can only be used … `` など、場面によって大きく変わる
- **守っているもの**: generic な関数や `?`、スレッドの境界などが要求する能力を、その型が本当に持っている
- **よくある原因**: `?` で、エラー型の変換（`From`）が無い。`Rc` や `RefCell` をスレッドに渡した（`Send` / `Sync` でない）。`!Unpin` な Future を、`Unpin` が要る場所に渡した

| 直し方 | 判断 |
| --- | --- |
| その trait を実装する（`From` を足す、など） | その型がその能力を持つべきなら |
| 型を変える（`Rc` → `Arc`、`RefCell` → `Mutex`） | スレッドをまたぐなら |
| 要求している側の境界を見直す | generic な関数の境界が、実際に必要なより厳しいことがある |

**本文**: [06-3](../06-error-handling/06-3-error-propagation.md)、[09-1](../09-advanced-type-system/09-1-phantom-data.md)、[09-3](../09-advanced-type-system/09-3-type-level-constraints.md)、[10-1](../10-concurrency/10-1-send-sync.md)、[11-2](../11-async/11-2-pin.md)

### E0283: 型が1つに決まらない

- **メッセージ**: `` type annotations needed for `Vec<_>` ``（場面によって `type annotations needed`。似たエラーに E0282・E0284 がある）
- **守っているもの**: どの実装を使うかを、コンパイラが推測で決めない
- **よくある原因**: 同じ型に、同じ trait の実装が複数ある（`impl Stack<i32>` と `impl Stack<String>`）。`parse()` や `collect()` の結果の型を書いていない

| 直し方 | 判断 |
| --- | --- |
| 型を書く（`parse::<u32>()`、`let v: Vec<_> = …`） | その場の直し方 |
| 型引数を associated type に変える | 「1つの型に実装は1つ」と決まっているなら、推論が効くようになる（04-3 の主題） |

**本文**: [04-3](../04-traits/04-3-associated-type.md)

### E0038: trait が `dyn` にできない

- **メッセージ**: `` the trait `Shape` is not dyn compatible ``（古いバージョンでは `` the trait `Shape` cannot be made into an object ``）
- **守っているもの**: `dyn Trait` は、中身の型を知らずにメソッドを呼ぶ仕組み。型を知らないと呼べないメソッド（`Self` を返す、generic なメソッドなど）があると成り立たない
- **よくある原因**: `fn new() -> Self` や `fn clone_me(&self) -> Self`、`fn f<T>(&self, t: T)` を持つ trait を `dyn` で使おうとした

| 直し方 | 判断 |
| --- | --- |
| そのメソッドに `where Self: Sized` を付け、`dyn` からは呼べないことにする | そのメソッドが `dyn` 経由で要らないなら |
| `dyn` をやめて generic（`impl Trait`）にする | 型がコンパイル時に決まるなら |
| trait を2つに分ける | `dyn` で使う部分と、使わない部分を分ける |

**本文**: [04-2](../04-traits/04-2-generic-vs-dyn.md)

### E0599: そのメソッドが見つからない

- **メッセージ**: `` no method named `go` found for struct `A` in the current scope ``
- **守っているもの**: その型（その状態）で呼べるメソッドだけを呼ぶ
- **よくある原因**: 綴りの間違い。trait のメソッドなのに、trait を `use` していない。**typestate で、その状態には無いメソッドを呼んだ**

typestate（Lesson 03-3）では、E0599 は「その状態ではできない操作」を知らせる、設計どおりのエラーです。

| 直し方 | 判断 |
| --- | --- |
| trait を `use` する | `help:` に候補が出ることが多い |
| 正しい状態に遷移してから呼ぶ | typestate なら、それがコンパイラの言いたいこと |

**本文**: [03-3](../03-enum-state-machine/03-3-typestate.md)

### E0184: `Drop` を持つ型を `Copy` にした

- **メッセージ**: `` the trait `Copy` cannot be implemented for this type; the type has a destructor ``
- **守っているもの**: コピーした分だけ片付けが走り、同じ資源（ファイルなど）を何度も閉じる、ということを起こさない
- **直し方**: `Copy` を外す（必要なら `Clone` にして、複製のしかたを自分で決める）

**本文**: [01-1](../01-ownership/01-1-move.md)

### E0392: 型引数を使っていない

- **メッセージ**: `` type parameter `T` is never used ``
- **守っているもの**: 型引数が、その型の性質（variance、`Send` かどうか、drop の扱い）にどう影響するかを、コンパイラが決められるようにする
- **よくある原因**: 「単位」や「状態」を表す目印として型引数を付けたが、フィールドでは使っていない

| 直し方 | 判断 |
| --- | --- |
| `PhantomData<T>` のフィールドを足す | 型引数を目印として使うなら。`PhantomData<fn() -> T>` などで、性質も選べる（09-1、09-2） |
| 型引数を消す | 目印として要らないなら |

**本文**: [09-1](../09-advanced-type-system/09-1-phantom-data.md)

## パターン

### E0004: `match` が全ての場合を扱っていない

- **メッセージ**: `` non-exhaustive patterns: `E::B` not covered ``
- **守っているもの**: 全ての場合に、何をするかが決まっている
- **よくある原因**: enum に variant を足した。`#[non_exhaustive]` な外部の enum を、`_` なしで `match` した

| 直し方 | 判断 |
| --- | --- |
| 足りない腕を書く | 自分の enum なら、基本はこれ。新しい variant で何をすべきか考える機会 |
| `_ =>` を書く | 外部の `#[non_exhaustive]` な enum なら必須。自分の enum で使うと、次に variant を足したときに、このエラーで気づけなくなる |

**本文**: [00-3](../00-introduction/00-3-diagnostic.md)、[02-1](../02-type-design/02-1-invalid-states.md)、[03-4](../03-enum-state-machine/03-4-non-exhaustive.md)、[P7](../17-projects/p07-iniconf.md)

## 可視性とモジュール

### E0451: 非公開のフィールドを使って値を作った

- **メッセージ**: `` field `x` of struct `P` is private ``
- **守っているもの**: 作るときの検証（`new` の中の確認）を、外から素通りさせない
- **直し方**: 用意された関数（`new`、`parse` など）で作る。フィールドを `pub` にするのは、「どんな値でも正しい」ときだけ

**本文**: [02-3](../02-type-design/02-3-parse-dont-validate.md)（関連: [02-4](../02-type-design/02-4-visibility.md)）

### E0603: 非公開の項目を使った

- **メッセージ**: `` function `f` is private ``
- **守っているもの**: モジュールが外に約束していない部分を、外から使わせない。約束していない部分は、自由に変えてよい
- **直し方**: 公開されている入口（`pub use` で並べた型など）を使う。自分のモジュールなら、それを公開すべきかを考えてから `pub` にする（`pub(crate)` で足りることも多い）

**本文**: [12-4](../12-architecture/12-4-dependencies-and-visibility.md)

### E0425: その名前が見つからない

- **メッセージ**: `` cannot find value `y` in this scope ``
- **よくある原因**: 綴りの間違い、`use` の書き忘れ。**マクロの中で作った変数を、マクロの外から使おうとした**（`macro_rules!` の衛生性: マクロの中の名前は、外の名前と混ざらない）
- **直し方**: 名前をマクロの引数として渡す

**本文**: [14-1](../14-macros/14-1-when-macros.md)

## ライブラリの変更で起きるもの

この2つは、ライブラリの**利用者の側**で起きるエラーです。
自分がライブラリを変更したとき、利用者のコードでこれが起きるなら、その変更は破壊的変更です。

### E0046: trait の項目を実装していない

- **メッセージ**: `` not all trait items implemented, missing: `b` ``
- **ライブラリの側で防ぐ方法**: trait にメソッドを足すときは、**既定の実装**を付ける

**本文**: [16-2](../16-library-design/16-2-semver.md)

### E0063: struct のフィールドが足りない

- **メッセージ**: `` missing field `y` in initializer of `P` ``
- **ライブラリの側で防ぐ方法**: 公開する struct に `#[non_exhaustive]` を付けるか、フィールドを非公開にして `new` やビルダーで作らせる

**本文**: [16-2](../16-library-design/16-2-semver.md)

## unsafe

### E0133: unsafe な操作を、`unsafe` の外で行った

- **メッセージ**: `` call to unsafe function `f` is unsafe and requires unsafe function or block ``（生ポインタの参照外しなら `dereference of raw pointer is unsafe …`）
- **守っているもの**: コンパイラが確かめられない約束を、**誰かが引き受けた**ことを、コードの上に明示させる
- **直し方**: `unsafe { … }` で囲む前に、その操作が要求する条件（ポインタが有効、長さが正しい、など）を満たしていることを確かめ、`// SAFETY:` のコメントに書く。できれば、条件を確かめる safe な関数で包む（15-2）

**本文**: [15-1](../15-unsafe/15-1-what-unsafe-means.md)
