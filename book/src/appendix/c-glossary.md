# C. 用語集

この教材に出てくる用語を、分野ごとにまとめました。
それぞれ「**何をしているか**」を先に、「**なぜ必要か**」を後に書いています。
名前を覚えるより、この2つを説明できることを目指してください。

「主に扱う場所」は、その用語を詳しく説明している Lesson です。
ページ内を検索（ブラウザの Ctrl+F / ⌘F、または mdBook の検索）すると、用語を探しやすくなります。

## 所有権と借用

| 用語 | 何をしているか | なぜ必要か | 主に扱う場所 |
| --- | --- | --- | --- |
| 所有権（ownership） | 1つの値には、持ち主（変数）が1つだけある。持ち主がスコープを抜けると、値が片付けられる | ガベージコレクタなしで、メモリの解放を**いつ・誰が**するかを、コンパイル時に決めるため | [01-1](../01-ownership/01-1-move.md) |
| move | 代入や関数への受け渡しで、持ち主が移る。移った後の元の変数は使えない | 2つの変数が同じメモリを持ち、2回解放する（二重解放）のを防ぐため | [01-1](../01-ownership/01-1-move.md) |
| `Copy` | 代入すると、move ではなくビット単位のコピーになる型の性質 | 数のような小さな値まで move だと不便。コピーしても意味が変わらない型だけに許す | [01-1](../01-ownership/01-1-move.md) |
| `Clone` | 明示的に `clone()` を呼んで、中身ごと複製する | コピーのコストがかかる複製を、コードの上で目に見えるようにするため | [01-1](../01-ownership/01-1-move.md) |
| `Drop` | 値が片付けられるときに呼ばれる処理を書く trait | ファイルを閉じる、ロックを外すなどの後片付けを、書き忘れないようにするため | [01-1](../01-ownership/01-1-move.md) |
| RAII | 資源（ファイル、ロック）の確保を値の作成に、解放を値の片付け（`Drop`）に結びつける書き方 | 早期リターンや panic があっても、解放が必ず行われるようにするため | [10-2](../10-concurrency/10-2-arc-mutex.md) |
| 借用（borrow） | 持ち主を変えずに、値を一時的に使わせる。`&T`（読むだけ）と `&mut T`（書き換える） | 関数に値を渡すたびに所有権を移す・返すのは不便なため | [01-2](../01-ownership/01-2-borrow-errors.md) |
| 借用の規則 | `&T` はいくつでも同時に作れる。`&mut T` は1つだけで、その間 `&T` も作れない | 読んでいる途中でデータが変わる、2か所から同時に書き換える、という事故を防ぐため | [01-2](../01-ownership/01-2-borrow-errors.md) |
| ぶら下がった参照（dangling reference） | 解放されたメモリを指している参照 | 読むと何が起きるか分からない。Rust はコンパイル時にこれを作らせない | [00-1](../00-introduction/00-1-how-to-use.md)、[08-1](../08-lifetimes/08-1-what-annotations-say.md) |

## ライフタイム

| 用語 | 何をしているか | なぜ必要か | 主に扱う場所 |
| --- | --- | --- | --- |
| ライフタイム（lifetime） | 参照が有効でいられる期間 | 参照が借り元より長く生きないことを、コンパイラが確かめるため | [08-1](../08-lifetimes/08-1-what-annotations-say.md) |
| ライフタイム注釈（`'a`） | 「この戻り値は、この引数から借りている」という**関係**を書く。期間を延ばすものではない | 関数のシグネチャだけを見て、借用の関係が分かるようにするため | [08-1](../08-lifetimes/08-1-what-annotations-say.md) |
| 省略規則（elision） | よくある形では、ライフタイム注釈を書かなくても、コンパイラが決まった規則で補う | 毎回 `'a` を書く手間を省くため | [08-3](../08-lifetimes/08-3-elision-and-static.md) |
| `'static` | 「プログラムの終わりまで有効でいられる」こと。型の境界（`T: 'static`）では「借りた参照を含まない」ことを表す | スレッドやタスクに渡す値が、元の関数より長く生きても大丈夫なことを保証するため | [08-3](../08-lifetimes/08-3-elision-and-static.md) |
| HRTB（`for<'a>`） | 「どんなライフタイム `'a` に対しても成り立つ」という境界 | 呼ぶ側が決めるのではなく、関数の中で作った参照を受け取るクロージャなどを表すため | [08-4](../08-lifetimes/08-4-hrtb.md) |

## 型の設計

| 用語 | 何をしているか | なぜ必要か | 主に扱う場所 |
| --- | --- | --- | --- |
| 不変条件（invariant） | 「この型の値なら、いつでも成り立っている」と約束する性質（例: `Email` には必ず `@` がある） | 使うたびに確かめ直さなくて済むようにするため | [02-3](../02-type-design/02-3-parse-dont-validate.md) |
| newtype | 既存の型を1つだけ持つ struct（`struct UserId(String)`） | 同じ `String` でも意味の違う値を、取り違えないようにするため。不変条件を持たせるため | [02-2](../02-type-design/02-2-newtype.md) |
| 構築時検証（parse, don't validate） | 値を作るときに1回だけ検証し、検証済みであることを型で表す | 「検証したか」を毎回気にしなくて済むようにするため | [02-3](../02-type-design/02-3-parse-dont-validate.md) |
| 状態機械（state machine） | 状態の一覧と、どの操作でどの状態に移るかの決まり | 「ありえない状態」「ありえない遷移」を設計の段階で洗い出すため | [03-1](../03-enum-state-machine/03-1-enum-states.md)、[03-2](../03-enum-state-machine/03-2-transitions.md) |
| typestate | 状態ごとに別の型を作り、その状態でできる操作だけをメソッドにする | 間違った順番の操作を、コンパイルエラーにするため | [03-3](../03-enum-state-machine/03-3-typestate.md) |
| `#[non_exhaustive]` | 外の crate からの `match` に `_` の腕を必須にする、構造体の直接の作成を禁じる | 後で variant やフィールドを足しても、利用者のコードを壊さないため | [03-4](../03-enum-state-machine/03-4-non-exhaustive.md) |
| ビルダー（builder） | 設定をメソッドで1つずつ決めてから、最後に値を作る書き方 | 引数が多い、既定値が多い値を、読みやすく作るため | [02-1](../02-type-design/02-1-invalid-states.md)、[16-1](../16-library-design/16-1-api-review.md) |

## trait と generic

| 用語 | 何をしているか | なぜ必要か | 主に扱う場所 |
| --- | --- | --- | --- |
| trait | 型が持つ「能力」（呼べるメソッドの組）を定義する | 異なる型を、同じ能力を持つものとして扱うため。**共通化のためだけに作るものではない** | [04-1](../04-traits/04-1-trait-purpose.md) |
| generic | 型を引数にして、1つの定義を複数の型で使う（`fn f<T>(x: T)`） | 型ごとに同じコードを書かずに済ませ、しかも型の情報を失わないため | [05-1](../05-generics/05-1-generic-benefit.md) |
| trait bound（`T: Display`） | 型引数に「この能力を持つこと」を要求する | generic な関数の中で、その能力（メソッド）を使えるようにするため | [05-2](../05-generics/05-2-trait-bounds.md) |
| 単相化（monomorphization） | generic な関数を、使われた型ごとに別々の関数としてコンパイルする | 実行時に型を調べるコストをなくすため（そのかわりバイナリは大きくなる） | [04-2](../04-traits/04-2-generic-vs-dyn.md) |
| 静的ディスパッチ | 呼ぶメソッドがコンパイル時に決まる（generic、`impl Trait`） | 速い。インライン化などの最適化も効く | [04-2](../04-traits/04-2-generic-vs-dyn.md) |
| trait object（`dyn Trait`） | 型を消して、「この trait を実装した何か」として扱う値 | 異なる型を1つの `Vec` に入れるなど、実行時に型が決まる場面のため | [04-2](../04-traits/04-2-generic-vs-dyn.md) |
| 動的ディスパッチ | 呼ぶメソッドが実行時に決まる（`dyn Trait`） | 型が実行時まで分からない場面で、それでもメソッドを呼べるようにするため | [04-2](../04-traits/04-2-generic-vs-dyn.md) |
| vtable | `dyn Trait` の値が持つ、「この型のメソッドはどこにあるか」の表 | 動的ディスパッチの仕組みそのもの | [04-2](../04-traits/04-2-generic-vs-dyn.md) |
| dyn 互換性（object safety） | trait を `dyn` で使えるための条件（`Self` を返さない、generic なメソッドを持たない、など） | 型を消した後でも、メソッドを呼べる必要があるため | [04-2](../04-traits/04-2-generic-vs-dyn.md)、[Appendix A の E0038](a-compiler-errors.md) |
| supertrait | 「この trait を実装するには、あの trait も実装していること」という要求（`trait A: B`） | ある能力が、別の能力を前提にしているときに表すため | [04-2](../04-traits/04-2-generic-vs-dyn.md) |
| associated type | trait の中で決める型（`Iterator` の `Item`） | 「1つの型に実装は1つ」と決まっているとき、使う側で型を書かずに済むようにするため | [04-3](../04-traits/04-3-associated-type.md) |
| `impl Trait` | 引数では「この trait を実装した何か」、戻り値では「具体的な型は隠すが、この trait を実装している」 | 長い型（iterator の組み合わせ、クロージャ）を書かずに済ませ、実装を隠すため | [05-3](../05-generics/05-3-impl-trait.md) |
| GAT（generic associated type） | 型引数やライフタイムを持つ associated type | 「自分自身から借りた値を返す iterator」など、借用の関係を trait で表すため | [05-4](../05-generics/05-4-gat-basics.md) |
| `PhantomData<T>` | 実際には `T` の値を持たないが、「`T` に関係する型だ」とコンパイラに伝えるフィールド | 型引数を目印（単位、状態）として使うため。variance や `Send` の判定を正しくするため | [09-1](../09-advanced-type-system/09-1-phantom-data.md) |
| variance（変性） | 型引数の中のライフタイムが長い・短いとき、型全体を置き換えてよいかの規則（共変・反変・不変） | 長く有効な参照を、短くてよい場所に渡せる一方で、危険な置き換えを防ぐため | [09-2](../09-advanced-type-system/09-2-variance.md) |
| zero-cost abstraction | 抽象化（iterator、generic）を使っても、手で書いた場合と同じくらい速いコードになる | 「読みやすさ」と「速さ」のどちらかを諦めなくて済むようにするため | [09-4](../09-advanced-type-system/09-4-zero-cost.md) |

## エラー処理と iterator

| 用語 | 何をしているか | なぜ必要か | 主に扱う場所 |
| --- | --- | --- | --- |
| `?` 演算子 | `Ok` なら中身を取り出し、`Err` ならその場で関数から返す。必要なら `From` でエラーの型を変換する | エラーを呼んだ側に伝える、決まりきったコードを短くするため | [06-3](../06-error-handling/06-3-error-propagation.md) |
| error propagation | 自分で処理できないエラーを、呼んだ側に渡す | エラーを、それを処理できる場所まで届けるため | [06-3](../06-error-handling/06-3-error-propagation.md) |
| library と application のエラー | library は利用者が**区別できる**型で返す。application は利用者（人）に**伝える**ことを重視する | エラーを受け取る相手が違うため | [06-4](../06-error-handling/06-4-library-vs-application.md) |
| iterator adapter | iterator を受け取り、別の iterator を返すメソッド（`map`、`filter`） | 処理を組み合わせて、途中の `Vec` を作らずに書くため | [07-1](../07-iterator/07-1-adapters-vs-for.md) |
| 遅延評価 | iterator は、`collect` や `for` で要素を求められるまで何もしない | 必要な分だけ計算し、途中の確保を減らすため | [07-3](../07-iterator/07-3-laziness-and-allocation.md) |

## 並行処理

| 用語 | 何をしているか | なぜ必要か | 主に扱う場所 |
| --- | --- | --- | --- |
| `Send` | その型の値を、別のスレッドに**渡して**よいという性質 | スレッドに渡すと危険な型（`Rc` など）を、コンパイル時に見つけるため | [10-1](../10-concurrency/10-1-send-sync.md) |
| `Sync` | その型の値を、複数のスレッドから**同時に参照**してよいという性質（`&T` が `Send`） | 同時に読むと危険な型（`Cell`、`RefCell`）を見つけるため | [10-1](../10-concurrency/10-1-send-sync.md) |
| データ競合 | 2つのスレッドが同じデータに同時にアクセスし、少なくとも片方が書き込むこと | 結果が実行のたびに変わる、最も見つけにくいバグの1つ。Rust はコンパイル時に防ぐ | [10-1](../10-concurrency/10-1-send-sync.md) |
| `Rc<T>` / `Arc<T>` | 1つの値を、複数の持ち主で共有する。最後の持ち主が消えると片付けられる。`Arc` はスレッド間でも使える版 | 持ち主を1つに決められない値（グラフ、共有する設定）のため | [10-2](../10-concurrency/10-2-arc-mutex.md) |
| `Mutex<T>` / `RwLock<T>` | ロックを取った人だけが中身を使える。`RwLock` は「読むだけなら同時に何人でも」 | 共有したデータを、スレッド間で安全に書き換えるため | [10-2](../10-concurrency/10-2-arc-mutex.md) |
| デッドロック | 2つのスレッドが、互いに相手の持つロックを待って止まること | コンパイラは防がない。ロックを取る順番をそろえるなど、設計で防ぐ | [10-2](../10-concurrency/10-2-arc-mutex.md) |
| interior mutability | `&T`（読むだけの参照）からでも、中身を書き換えられるようにする仕組み（`Cell`、`RefCell`、`Mutex`） | 外から見て変わらないが、中で記録を更新したい（キャッシュ、回数）場面のため | [10-3](../10-concurrency/10-3-interior-mutability.md) |
| `Cell<T>` / `RefCell<T>` | 1つのスレッドの中での interior mutability。`RefCell` は借用の規則を実行時に確かめる | コンパイル時には借用の規則を確かめられない構造を扱うため | [10-3](../10-concurrency/10-3-interior-mutability.md) |
| アトミック（`AtomicU64` など） | ロックを使わずに、1つの数を安全に読み書き・加算する | 回数を数えるだけのために、ロックを取らなくて済むようにするため | [10-2](../10-concurrency/10-2-arc-mutex.md)、[P5](../17-projects/p05-cache.md) |
| チャネル（`mpsc`） | スレッド間で、値を送って受け取る | データを共有するかわりに、持ち主ごと渡すため（「共有せずに送る」） | [10-4](../10-concurrency/10-4-message-passing.md) |

## async

| 用語 | 何をしているか | なぜ必要か | 主に扱う場所 |
| --- | --- | --- | --- |
| `Future` | 「いつか値が得られる計算」。`poll` されるたびに少し進み、終わったら値を返す | 待ち時間の多い仕事を、少ないスレッドでたくさん抱えるため | [11-1](../11-async/11-1-what-is-a-future.md) |
| `async` / `.await` | `Future` を、ふつうの関数のような書き方で作る・待つ構文 | `poll` を手で書く状態機械を、コンパイラに作らせるため | [11-1](../11-async/11-1-what-is-a-future.md) |
| `Waker` | 「この Future は、もう一度 poll すれば進む」とランタイムに知らせる仕組み | 進めない Future を何度も poll する無駄をなくすため | [11-1](../11-async/11-1-what-is-a-future.md) |
| ランタイム（executor） | Future を poll して完了まで進める仕組み。tokio など | Rust の標準ライブラリは Future を**動かす**仕組みを持たないため | [11-1](../11-async/11-1-what-is-a-future.md)、[11-4](../11-async/11-4-async-vs-threads.md) |
| `Pin` | 値をメモリ上で動かせないようにする | async が作る Future は、自分自身の中を指す参照を持つことがあり、動かすと壊れるため | [11-2](../11-async/11-2-pin.md) |
| `Unpin` | 「動かしても問題ない」という性質。ほとんどの型は `Unpin` | `Pin` の制約が要らない型では、制約を外して扱えるようにするため | [11-2](../11-async/11-2-pin.md) |
| 並行（concurrency）と並列（parallelism） | 並行は、複数の仕事を切り替えながら進めること。並列は、複数の CPU で同時に動かすこと | async が直接くれるのは並行。並列はランタイムのスレッドプールによる | [11-4](../11-async/11-4-async-vs-threads.md) |
| 中断（キャンセル） | Future を途中で捨てる（drop する）と、処理はそこで終わる | timeout などで処理を止める仕組み。後片付けは `Drop` に任せる | [P6](../17-projects/p06-fetch-all.md) |
| 背圧（backpressure） | 受け取る側が追いつくまで、送る側を待たせる | 仕事が溜まりすぎてメモリを使い切るのを防ぐため | [P6](../17-projects/p06-fetch-all.md) |

## モジュールとテスト

| 用語 | 何をしているか | なぜ必要か | 主に扱う場所 |
| --- | --- | --- | --- |
| 可視性（`pub`、`pub(crate)`） | 項目を、どこから使えるようにするかを決める | 外に約束していない部分を、自由に変えられるようにするため | [12-1](../12-architecture/12-1-module-boundaries.md)、[12-4](../12-architecture/12-4-dependencies-and-visibility.md) |
| facade | 中のモジュールは非公開にし、使ってほしい型だけを crate の直下に `pub use` で並べる | ファイルの分け方を変えても、利用者の `use` を壊さないため | [12-4](../12-architecture/12-4-dependencies-and-visibility.md) |
| lib と bin の分離 | ロジックを `lib.rs` に、起動と入出力だけを `main.rs` に置く | ロジックをテストから呼べるようにするため | [12-2](../12-architecture/12-2-lib-and-bin.md) |
| workspace | 複数の crate を、1つのリポジトリでまとめてビルド・テストする | crate の境界で、依存の向きを強制するため（crate 間は循環できない） | [12-3](../12-architecture/12-3-workspaces.md) |
| 依存性の注入 | 必要なもの（時計、通信）を中で作らず、外から渡してもらう | テストで偽物に差し替えられるようにするため | [13-1](../13-testing/13-1-testable-design.md) |
| 単体テスト / 統合テスト / doctest | モジュールの中のテスト / `tests/` の、公開 API だけを使うテスト / ドキュメントのコード例を実行するテスト | 確かめたいもの（内部の部品、外への約束、ドキュメントの正しさ）が違うため | [13-2](../13-testing/13-2-kinds-of-tests.md) |
| `#[should_panic]` | 「このテストは panic すれば成功」という指定 | panic すべき場面を確かめるため。`expected` で panic の内容も確かめる | [13-3](../13-testing/13-3-testing-failures.md) |

## マクロと unsafe

| 用語 | 何をしているか | なぜ必要か | 主に扱う場所 |
| --- | --- | --- | --- |
| 宣言的マクロ（`macro_rules!`） | コードの形のパターンに合わせて、コードを生成する | 関数や generic では書けない繰り返し（型ごとの impl、可変個の引数）のため | [14-2](../14-macros/14-2-macro-rules.md) |
| 衛生性（hygiene） | マクロの中で作った変数名が、外の変数名と混ざらない | マクロを使った場所の変数を、うっかり上書きしないため | [14-1](../14-macros/14-1-when-macros.md) |
| 手続き的マクロ（procedural macro） | Rust のコードを受け取り、Rust のコードを返す関数としてマクロを書く（`#[derive(...)]` など） | 型の定義を読んで impl を生成するなど、パターンでは書けない変換のため | [14-3](../14-macros/14-3-proc-macros.md) |
| `unsafe` | コンパイラが確かめられない操作（生ポインタの参照外し、FFI など）を行う場所の印 | 規則を緩めるのではなく、「ここの約束は書いた人が引き受けた」と明示するため | [15-1](../15-unsafe/15-1-what-unsafe-means.md) |
| 未定義動作（UB） | 言語が「起きてはならない」と定めた状態。起きると、何が起きても保証されない | コンパイラの最適化はこれが起きない前提で行われるため、起きると結果が予測できない | [15-2](../15-unsafe/15-2-safe-abstraction.md) |
| safe abstraction | `unsafe` を中に閉じ込め、外からは safe な関数だけを見せる | どんな使い方をしても未定義動作に届かない、という保証を利用者に渡すため | [15-2](../15-unsafe/15-2-safe-abstraction.md) |
| FFI | 他の言語（主に C）の関数を呼ぶ・呼ばれる仕組み（`extern "C"`） | 既存の C のライブラリや OS の機能を使うため | [15-3](../15-unsafe/15-3-ffi.md) |

## ライブラリの設計

| 用語 | 何をしているか | なぜ必要か | 主に扱う場所 |
| --- | --- | --- | --- |
| semver | バージョン番号 `MAJOR.MINOR.PATCH` で、変更が利用者のコードを壊すかどうかを伝える約束 | 利用者が、安全に更新できるかを判断できるようにするため | [16-2](../16-library-design/16-2-semver.md) |
| 破壊的変更 | 利用者のコードがコンパイルできなくなる、または動きが変わる変更 | MAJOR を上げる必要がある。公開する前に避け方を考える | [16-2](../16-library-design/16-2-semver.md) |
| 既定の実装（default method） | trait のメソッドに、中身をあらかじめ書いておく | 後から trait にメソッドを足しても、既存の実装を壊さないため | [16-2](../16-library-design/16-2-semver.md) |
