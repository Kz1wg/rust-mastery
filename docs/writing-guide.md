# 執筆ガイド

この教材の対象は「Rust を書いたことがある初中級者」です。
本文を書く・直すときは、次の基準に合わせてください。

## 4つの基準

1. **用語は、名前より先に「やっていること」を説明する**
   - 良い例: 「必要なものを中で作らず、外から渡してもらう。これを依存性の注入と呼ぶ」
   - 悪い例: 「依存性の注入を使う」（説明なし）
   - 専門用語は、**その教材の中で初めて出てくる場所**で説明する。2回目以降は説明しなくてよい

2. **抽象的な説明の前に、身近な困りごとや具体例を置く**
   - 例: 13-1 は「夜に CI が動くと落ちるテスト」から始める
   - たとえ話を使ってよい（09-2 の有効期限つきチケット、11-1 のフードコートの呼び出しベル）

3. **1文に詰め込みすぎない**
   - 専門用語が3つ以上並ぶ文は、分けるか、表にする
   - 型のシグネチャ（`Pin<&mut Self>` など）を冒頭に置かない。説明の後で「実際の定義はこう」と示す

4. **判断に迷う場面には、目安の表を置く**
   - 「どちらを選ぶか」「どれを書けばよいか」は、状況と選択肢の表にする

## その他の約束

- Lesson の構成は DESIGN.md §5 のとおり（Concept → Why? → Bad Example → … → Review）
- 主張は実機で確かめてから書く。確かめられないことは断定しない（「〜になることが多い」「Rust 1.75 で確認」）
- エラーコードを書いた `compile_fail` は、`tools/check_error_codes.py` で一致を確認する
